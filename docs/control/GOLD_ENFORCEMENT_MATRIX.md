## Visual protection

`docs/control/GOLD_VISUAL_BASELINES.json` is the visual lock registry.

- `CANDIDATE` = evidence is collected but is not Founder-approved and never blocks future visual change by itself.
- `APPROVED` = requires an exact SHA-256 image hash plus a Founder decision reference. CI blocks silent hash drift.
- `RETIRED` = preserved history, no longer active baseline.

CI must never promote a CANDIDATE screenshot to APPROVED by inference.

## Machine-enforced gates

The repository must run `scripts/gold-policy-check.mjs` on:
- TEST KING pushes;
- pull requests targeting `main`;
- future `main` pushes as detection/verification.

For user-facing changes it verifies the current GOLD brief changed in the same bounded change and required authority files exist. For a pull request to `main`, product code is rejected when the source is not `king/test`. A future LIVE promotion requires a populated `docs/control/LIVE_PROMOTION_MANIFEST.json` with Founder acceptance and rollback identity.

This policy is additive to TypeScript, build, smoke/contracts, asset, security, dependency, Chromium, WebKit, mobile, context, truth and rights gates. It never replaces them.
