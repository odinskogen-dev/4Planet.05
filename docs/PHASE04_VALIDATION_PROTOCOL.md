# 4PLANET_ PHASE 04 — HUMAN VALIDATION PROTOCOL

Status: **READY TO RUN / HUMAN RESULTS NOT RUN**

This protocol tests whether an intelligent non-specialist can understand, remember and want to use the Phase 04 candidate without reading brand strategy.

AI review, founder judgement and CI are useful but **must not be labelled human validation**.

## 1. Primary research question

Can a person who has never seen the strategy infer that 4PLANET helps them:

1. see a living place / planetary context;
2. begin with life;
3. understand relationships and pressures;
4. follow meaningful change;
5. find a credible role/action when one exists;
6. distinguish activity, reporting and proof?

## 2. First sample

Recommended first qualitative/quantitative proof sample: **12–20 participants**.

Recruit across:
- 8–12 intelligent non-specialists with no professional environment/climate role;
- 2–4 people working in science/data/conservation/public administration;
- 2–4 people with product/design/media/partner/funder perspective.

Avoid a sample dominated by friends who already know 4PLANET. Record prior awareness before exposure.

This sample is for directional product evidence, not population-level market measurement.

## 3. Stimulus control

Use the same Phase 04 branch build for every participant in a wave.

Required stimuli:
- `/` — Living Place-first front door;
- `/place/oslofjorden`;
- `/living-systems`;
- `/missions/am4zonia`;
- `/missions/wh4les`;
- `/missions/clim4te`;
- Proof State component;
- one logo-hidden screenshot of Relationship Reveal;
- one logo-hidden mission screenshot;
- one competing/generic environmental interface stimulus only if rights permit.

Randomise mission order. Do not explain product architecture before the first tasks.

## 4. Five-second comprehension

Show only the top viewport of `/` for five seconds, then hide it.

Ask verbatim:
1. “What do you think this is?”
2. “What do you think you can do here?”
3. “What do you remember seeing?”
4. “What kind of organisation or product do you think made it?”

Code answers without forcing 4PLANET vocabulary.

### Proposed Phase 04 pass signal
- ≥70% independently mention at least one of: planet/place/life/nature plus understand/explore/follow/data/action.
- ≤30% classify it only as a generic NGO/donation site, magazine, consultancy or marketing campaign.

These are **proposed internal thresholds**, not validated industry norms.

## 5. Thirty-second comprehension

Allow 30 seconds on the front door with scrolling.

Ask:
- “What are the main things this product lets you do?”
- “What is ATLAS for?”
- “What is SPECIES for?”
- “What is Living Systems doing here?”
- “What is IMPACT for?”
- “Which of these feels like a separate company/app, if any?”

### Proposed pass signal
- ≥70% correctly distinguish at least three of the four product jobs.
- ≥70% understand Living Systems as an understanding/relationship layer rather than a fifth unrelated app.
- <25% describe the system as four unrelated websites.

## 6. Oslofjorden journey task

Prompt:

“Find out what 4PLANET currently knows, what it does not yet know, and what changed recently around Oslofjorden.”

Observe without coaching:
- Can the participant locate LIFE / PRESSURE / SIGNAL / FOLLOW / ACTION / PROOF?
- Do they notice `CURATED SOURCE`, `PROTOTYPE DATA`, `NOT YET IMPLEMENTED`?
- Do they interpret missing implementation as honesty or as product failure?
- Can they explain the policy Signal in their own words?
- Do they wrongly infer that 4PLANET currently runs an Oslofjord field project?

Critical fail:
- participant reasonably concludes that a demo fixture is a live animal observation, an actual partner activity or a verified ecological outcome.

## 7. Relationship Reveal comprehension

Show THREAD first, then let user switch to ORBIT and CONSTELLATION.

Ask:
- “What is this showing?”
- “Which view makes the relationship easiest to understand?”
- “Which view would you choose if you wanted to explore deeper?”
- “Does any connection look more certain than the interface has evidence for?”

Record:
- default comprehension;
- mode preference by task;
- perceived causality strength;
- visual distinctiveness.

Primary hypothesis:
- THREAD wins comprehension/default use;
- ORBIT wins cinematic/hero appeal;
- CONSTELLATION wins deep exploration but has higher orientation cost.

Do not call the hypothesis validated until respondents support it.

## 8. Proof State comprehension

Show examples of:
- SOURCE;
- 4PLANET CONTEXT;
- PARTNER REPORT;
- ASSESSED OUTCOME;
- VERIFIED OUTCOME.

Ask participants to rank which claims are strongest and explain why.

Critical question:

“Does PARTNER REPORT mean 4PLANET independently verified the result?”

Proposed pass signal:
- ≥80% answer **no** after normal exposure, without researcher explanation.

Also test flags:
UNCERTAIN / CONTESTED / CORRECTED / SUPERSEDED.

## 9. Mission-family recognition

First expose participant to one mission world without explaining the hierarchy.

Ask:
- “What is AM4ZONIA_ / WH4LES_ / CLIM4TE_?”
- “Who is behind it?”
- “Would you expect the same account/navigation/evidence standards elsewhere?”
- “What does the 4 in the name communicate, if anything?”

Then show all three together and ask which elements make them feel related.

Proposed pass signal:
- ≥70% identify the mission as part of 4PLANET after first normal exposure.
- ≥70% understand the plain-language subject.
- coded spelling should not materially reduce subject comprehension.

## 10. Logo-hidden attribution / distinctiveness

After product exposure, show crops without the 4PLANET wordmark:
- THREAD relationship view;
- Provenance Bar;
- mission first exposure;
- Signal object;
- documentary-life + paper/ink composition.

Ask:
- “Which product do you think this came from?”
- “What made you think that?”

This does **not** measure existing market recognition. It only tests whether the prototype builds consistent internal memory structures after exposure.

## 11. Trust

Use 1–7 ratings only after open-ended questions:
- I understand what is source material versus 4PLANET interpretation.
- I can tell when something is unfinished.
- I can tell the difference between an activity/report and a verified result.
- I would trust this product enough to inspect the source before acting on it.

Immediately ask “Why?” after each low/high extreme.

## 12. Desire to explore and return

Ask:
- “What would you click next?”
- “Is there anything here you would follow over time?”
- “What would need to change for you to come back next week?”
- “Would a meaningful Signal bring you back, or would you rather use another source?”

Measure:
- chosen next route;
- voluntary exploration depth;
- follow intent;
- return intent;
- expected update value.

## 13. Unaided recall

After 20–30 minutes of unrelated tasks, ask:
- brand name;
- one product/job;
- one visual/interaction behaviour;
- one mission name;
- what made it different.

Optional stronger test: repeat after ~24 hours.

Do not prompt with `4`, blue, Signal, Relationship Reveal or Proof.

## 14. Confusion matrix

Ask participants to allocate 100 points across what 4PLANET feels most like:
- public-interest planetary product/platform;
- NGO/charity;
- media/editorial publication;
- consultancy;
- scientific/data dashboard;
- action/impact marketplace;
- other.

Desired result is not zero association with all adjacent categories. The failure is that one narrow adjacent category overwhelms the intended integrated product understanding.

## 15. Researcher record

For every participant record:
- participant ID only;
- cohort;
- prior 4PLANET awareness;
- device;
- exact candidate SHA;
- exact stimulus order;
- open-ended raw answers;
- task completion;
- notable hesitation/confusion;
- rating responses;
- researcher notes clearly separated from participant statements.

Do not store unnecessary personal data.

## 16. Analysis output

Produce separately:

### HUMAN FINDINGS
Only observed respondent evidence.

### AI / DESIGN EVALUATION
Model or expert interpretation.

### FOUNDER JUDGEMENT
Strategic decision after seeing artefacts + human evidence.

Never merge these evidence classes.

## 17. Release decision rule

Do not make external validation a false binary. Classify each hypothesis:
- SUPPORTED;
- MIXED;
- NOT SUPPORTED;
- INSUFFICIENT SAMPLE;
- BLOCKED BY IMPLEMENTATION.

Founder review should receive:
1. raw signal summary;
2. strongest evidence against the current candidate;
3. repaired prototype if reversible;
4. only remaining strategic choices.
